# Issue #142: `slugify` fails to collapse multi-dash runs on Unicode/punctuation input and leaves trailing separators on `max_length`

## Summary

`textutils.slug.slugify` produces malformed slugs in two common cases:

1. **Consecutive separators are not fully collapsed**:
   When input contains multiple consecutive spaces/punctuation or Unicode punctuation sequences (such as `" — "`, `"---"`, or `"・・・"`), `slugify` only replaces `"--"` with `"-"` once instead of collapsing arbitrary-length runs of the separator into a single separator.
2. **Leading/trailing separator stripping order with `max_length`**:
   `slugify` strips separators only before slicing `[:max_length]`. When `max_length` slices right on a separator boundary, the returned slug retains a trailing separator.

## Reproduction Examples

| Call | Actual (Buggy) | Expected |
| :--- | :--- | :--- |
| `slugify("Café — Crème")` | `"cafe--creme"` | `"cafe-creme"` |
| `slugify("Hello --- World!!!")` | `"hello---world"` | `"hello-world"` |
| `slugify("東京・・・タワー", allow_unicode=True)` | `"東京--タワー"` | `"東京-タワー"` |
| `slugify("   ---Multiple   Spaces & Symbols---   ")` | `"multiple--spaces---symbols"` | `"multiple-spaces-symbols"` |
| `slugify("hello world", max_length=6)` | `"hello-"` | `"hello"` |
| `slugify("  --leading-and-trailing--  ", max_length=8)` | `"leading-"` | `"leading"` |
